## 后端缓存持久化改造（globalCache）
- 问题：`server/services/globalCache.js` 原本是纯内存 `Map`（`this.cache = new Map()`），无 Redis、无落盘，应用重启后数据缓存与统计计数器全部丢失，导致冷启动期外部 API 调用骤增。
- 改动（分支 `dev`）：新增文件持久化，让缓存条目 + stats 计数器跨重启保留。
  - `globalCache.js`：新增 `fs/fsp/path` 依赖、`cacheFilePath`（默认 `server/data/globalCache.json`，可用 `CACHE_FILE_PATH` 覆盖）；`saveToFile()`（写 tmp 再原子 rename）、`saveToFileSync()`（退出钩子同步落盘）、`loadFromFile()`（恢复条目且恢复全部 stats：hits/misses/totalRequests/evictions/forcedRefreshes，丢弃过期条目）、`startPersistence(60s)`（周期落盘 + 注册 SIGINT/SIGTERM/beforeExit）。
  - `app.js`：启动 `app.listen` 前 `await globalCache.loadFromFile()`，并调用 `startPersistence()` 与 `startCleanup()`（顺手启用此前未调用的清理定时器）。
- 验证：`node --check` 两文件通过；往返测试证明条目与计数器（命中率 80%）重启后完整恢复。
- 已删除临时测试文件 `server/test_cache_persist.js`。

- 边界：仅单进程有效；多实例/集群仍需 Redis（本次未做）；`kill -9` 丢最近 ≤60s 增量；realtime TTL 28s 重启后基本判过期丢弃（预期）。
